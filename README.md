# stability-guard

Фоновый демон для macOS: держит систему отзывчивой, следит за памятью и системными
ошибками, а после каждого инцидента просит Claude написать короткий отчёт.

**Без API-ключа.** Отчёты идут через CLI `claude -p` — то есть через твою подписку.

## Что он делает

1. **Throttling.** Каждые 15 секунд смотрит активное окно. Приложения не в фокусе и не
   в whitelist, которые жрут CPU, понижаются через `taskpolicy -b -p PID`.
   Вернулось в фокус — приоритет восстанавливается тем же тиком (`taskpolicy -B`).
2. **Memory watchdog.** Читает `sysctl kern.memorystatus_vm_pressure_level`
   (1=норма, 2=warning, 4=critical). При critical — уведомление с топ-5 по RSS.
3. **Системные ошибки.** Следит за новыми crash-репортами в `DiagnosticReports`
   (`.ips`, `.crash`, `.panic`, `.hang`). Новый файл → уведомление + попадает в отчёт.
4. **Отчёт.** Когда инцидент закончился (память в норме И прошло N минут), демон
   отправляет факты в `claude -p` вместе с последними 10 записями истории и
   инструкцией «не повторяй уже данные рекомендации».

## Чего он НЕ делает

Не убивает процессы. Не удаляет файлы. Не трогает системные настройки, swap и
Spotlight. Единственное действие — обратимое понижение приоритета своих же
пользовательских процессов. Claude вызывается с `--allowed-tools ""` — он может
только вернуть текст, никаких инструментов у него нет.

## Установка

```bash
cd ~/Desktop/stability-guard
./install.sh
```

Скрипт сам найдёт `python3` и `claude`, скопирует файлы, соберёт plist и загрузит
агент. Запускать повторно безопасно — существующий конфиг не перезатрёт.

**Одно разрешение вручную:** при первом запуске macOS спросит доступ к Accessibility
(нужен для определения активного окна). System Settings → Privacy & Security →
Accessibility → включить `python3`. Без него throttling не заработает, остальное — да.

## Проверка

```bash
# агент загружен? (второе поле = код выхода, должно быть 0)
launchctl list | grep stability-guard

# что происходит прямо сейчас
tail -f ~/.local/share/stability-guard/daemon.log

# разовый самотест сенсоров без установки
python3 stability_guard.py --selfcheck
```

Живой тест throttling: запусти что-нибудь тяжёлое (Docker, сборку), переключись в
другое окно, подожди 15-30 секунд — в логе появится `throttled ...`. Вернись в
приложение — появится `restored ...`.

В логе есть строки `focus: <приложение>` при каждой смене активного окна. Если там
`(неизвестно - нет доступа к Accessibility)` — значит разрешение не выдано, и
защита приложения «по фокусу» не работает (whitelist при этом работает).

Проверить восстановление приоритета, не трогая окна: добавь приложение в
`whitelist` в конфиге — через тик в логе появится `restored ...`.

## Уведомления

Демон присылает через Центр уведомлений macOS:

| Когда | Текст |
|---|---|
| Память на уровне warning | «Память под давлением» + топ-3 по RSS |
| Перед понижением приоритета | «Система под нагрузкой — понижаю приоритет X» |
| Память critical | «Критическое давление на память» + топ-3 |
| Новый крэш-репорт | «Системная ошибка» + имена файлов |
| Момент обращения к Claude | «Спрашиваю Claude» |
| Отчёт записан | «Отчёт от Claude готов» + первая строка |

Одно уведомление на инцидент, не на каждое приложение и не на каждый тик
(дедуп — `notify_dedupe_seconds`, по умолчанию 120 с).

Проверить, что канал работает:

```bash
python3 stability_guard.py --test-notify   # пришлёт по одному каждого типа
```

### Чтобы точно замечать

Каждое уведомление приходит со звуком: обычные — `Submarine`, критические
(память на пределе, крэш) — `Basso`. Меняется в конфиге:

```json
"notify_sound": "Submarine",        // любое имя из /System/Library/Sounds
"notify_sound_critical": "Basso",   // "" = без звука
```

Доступны: `Basso, Blow, Bottle, Frog, Funk, Glass, Hero, Morse, Ping, Pop, Purr,
Sosumi, Submarine, Tink`.

Ещё сильнее: System Settings → Notifications → **Script Editor** → стиль
**Alerts** вместо Banners. Тогда уведомление висит на экране, пока не закроешь.

### Иконка и имя

По умолчанию уведомления приходят от имени «Script Editor» с его иконкой —
так работает `osascript`, своей identity у него нет. Если хочется своё имя,
иконку и открытие `history.md` по клику:

```bash
brew install terminal-notifier
```

Демон подхватит его автоматически, менять конфиг не нужно.

## Подтверждение действий

По умолчанию демон действует сам. Если хочешь контролировать каждое понижение:

```json
"confirm_before_throttle": true,
"confirm_mode": "banner",       // или "dialog"
"confirm_timeout_seconds": 20
```

**`banner`** — уведомление выезжает справа сверху: «Понижу приоритет Figma через
20 с, нажми, чтобы отменить». Не мешает работе. Без клика действие выполнится.

**`dialog`** — модальное окно по центру с кнопками «Понизить / Не сейчас /
Никогда». Строже: без явного нажатия **ничего не произойдёт**, молчание = отказ.
Кнопка «Никогда» добавляет приложение в whitelist навсегда.

В обоих режимах ответ запоминается на приложение до перезапуска демона — тебя
не спросят про одно и то же каждые 15 секунд.

### Если уведомлений не видно

Первым делом проверь **Focus** — при активной focus-сессии (в том числе из Motion,
Slack или Календаря) macOS прячет баннеры, но складывает уведомления в Центр
уведомлений. Открой его кликом по часам — если там всё есть, канал работает.

Чтобы предупреждения пробивались сквозь Focus: System Settings → Focus → твой
режим → Allowed Notifications → добавить приложение-отправитель.

## История отчётов

```bash
open ~/.local/share/stability-guard/history.md
```

Каждая запись — факты инцидента + текст от Claude. Файл только дописывается.

## Настройка

`~/.config/stability-guard/config.json` — перечитывается на лету, перезапуск не нужен.

| Ключ | Что делает |
|---|---|
| `whitelist` | Приложения, которые никогда не понижаются |
| `min_cpu_percent` | Порог CPU, ниже которого фоновое приложение не трогаем |
| `report_delay_minutes` | Через сколько после начала инцидента просить отчёт |
| `min_report_interval_minutes` | Cooldown — защита лимитов подписки |
| `notify_every_throttle` | `true` = уведомление на каждое понижение (шумно) |
| `ai_enabled` | `false` = писать факты в историю без вызова Claude |
| `use_renice` | См. ограничение ниже. По умолчанию `false` |

Имена приложений — как в Activity Monitor (например `Google Chrome`, не `Chrome`).

## Отключить

```bash
# временно
launchctl bootout gui/$UID/com.user.stability-guard

# обратно
launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.user.stability-guard.plist

# полностью
./uninstall.sh
```

## Известные ограничения (важно)

- **`renice` необратим без root.** Понизить приоритет может любой пользователь,
  а поднять обратно — только root. Поэтому основной механизм — `taskpolicy -b/-B`,
  он обратим. `use_renice` оставлен как опция, но включать его без sudoers не стоит:
  приложение останется с пониженным nice до перезапуска.
- **Swap не трогается.** Безопасно управлять свопом на macOS без перезагрузки
  нельзя — демон только сообщает о давлении на память.
- **Лимиты подписки.** `claude -p` расходует тот же лимит, что и обычная работа
  в Claude Code. Отсюда cooldown в 30 минут и агрегация всех событий инцидента
  в один запрос вместо запроса на каждое событие.
- **launchd и переменные окружения.** launchd не наследует окружение шелла —
  `export` в `~/.zshrc` агент не увидит. Поэтому `PATH` и `HOME` прописаны прямо
  в plist (секция `EnvironmentVariables`), а полный путь к `claude` подставляется
  в конфиг при установке. Если понадобится добавить переменную — либо в plist,
  либо `launchctl setenv KEY value` (не переживает перезагрузку).
- **ChatGPT вместо Claude.** Технически можно подменить `claude_bin` на
  `codex exec`, но формат вывода другой и режим песочницы придётся настраивать
  отдельно — сейчас поддержан только `claude`.
